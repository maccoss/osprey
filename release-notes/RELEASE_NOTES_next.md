# Osprey Release Notes (Next Release)

Working draft for the next release. Append entries here as features and fixes land on the development branch. At release time this file is renamed to `RELEASE_NOTES_v{version}.md` and the workspace `Cargo.toml` version is updated to match.

## New Features

- **`--fdrbench <path>` flag** (native, Rust): writes an [FDRBench](https://github.com/Noble-Lab/FDRBench)-compatible input TSV directly from the pre-compaction first-pass FDR pool. The output includes **every scored target** (not just FDR-passing ones), with the raw SVM discriminant as `score` and the q-value matching `--fdr-level` (Both emits precursor-level; Protein writes the picked-protein TSV from the first-pass parsimony result). Decoys are excluded per FDRBench convention; entrapment sequences (carrying `_p_target` on protein accessions) pass through unchanged. Add `--fdrbench-per-run` to emit one row per (precursor, run) using run-level q-values. Invoke FDRBench with `-score 'score:1'`. Verified on Astral entrapment data: 2.5M target rows emitted (20x the blib's FDR-passing count), 1.23M entrapment rows preserved, zero decoys, spearman(score, q_value) = -0.97 within the FDR-passing subset.

- **`scripts/build_fdrbench_input.py`**: companion utility for the cases where you don't have access to the source data Osprey scored from. Reads either a DIA-NN `report.parquet` or an Osprey `.blib` (+ companion `.proteins.csv`) and emits the same FDRBench TSV format at peptide/precursor/protein level. `score` is the raw upstream discriminant (DIA-NN `Evidence`, Osprey blib `DiscriminantScore` with `1 - q_value` fallback when the blib doesn't carry it, `best_peptide_score` for protein groups from the Osprey proteins CSV). The native `--fdrbench` flag is preferred for Osprey results (the blib only contains FDR-passing entries); the script is the right choice for DIA-NN parquets and for after-the-fact analysis of existing blibs.

- **Library-supplied decoys** (`--decoys-in-library`): Osprey now correctly trusts decoys already present in the spectral library instead of generating them from targets. Library entries whose protein accession matches one of the configured `decoy_prefixes` (default: `DECOY_`, `rev_`, `decoy_`, case-insensitive) get `is_decoy = true` and the high bit set on their `id`. Set via the new `--decoys-in-library` CLI flag or `decoys_in_library: true` in YAML; customize the prefix list via `decoy_prefixes` in YAML. Osprey now bails with a clear error if the flag is set but no entries match.

- **Target-decoy pairing for library decoys (hybrid: manifest + composition fallback)**: marking alone is not enough — the SVM, LDA calibration, and CV fold splitting all rely on each decoy sharing a `base_id` with its target. Osprey now runs a two-stage pairing pass after decoy marking. **Stage 1**: when `--decoy-pairing-manifest <PATH>` is supplied, read a FDRBench-style 5-column TSV (`sequence`, `decoy`, `proteins`, `peptide_type`, `peptide_pair_index`) and link target↔decoy and `p_target`↔`p_decoy` within each `peptide_pair_index` group, honoring charge state. **Stage 2** (always runs): composition-based fallback on any decoys the manifest didn't cover — for each unpaired decoy, strip the configured prefix from each protein accession to recover the target accession, then find a target peptide with the same `(stripped_accession, charge, sorted_amino_acid_composition)`. Within a composition group on a single protein, entries are sorted by `(sequence, id)` and zipped 1:1 deterministically. The hybrid is important in practice: a manifest generated alongside a Carafe-style library typically misses 60-70% of the library's peptides because the library generator and FDRBench use different digestion rules, and composition pairing recovers them. Osprey logs the breakdown (`paired N/M (X%) - A via manifest, B via composition`) and **bails with a hard error if fewer than `decoy_pair_min_fraction` (default 80%) of decoys pair successfully overall** — FDR estimates would be unreliable otherwise. New `PairingState` type carries already-claimed/paired indices between the two passes; 15 unit tests cover composition pairing edge cases (multi-peptide composition groups, shared peptides, charge-state separation, determinism), manifest reader correctness, and the hybrid handoff.

- **Decoys detected via both the TSV `Decoy` column AND protein-prefix scan**: the DIA-NN TSV library loader now reads the optional `Decoy` column (accepts `1`, `true`, `yes`, `y`, `t` — case-insensitive) and flags those entries as decoys at load time. The protein-prefix scan (`decoy_` / `rev_` / `DECOY_`) still runs on top, so libraries that set ONLY the column, ONLY the prefix, or BOTH all work correctly. Useful because Carafe-generated libraries reliably set the protein-accession prefix but not the `Decoy` column; the loader now handles either signal so no post-processing is required. The pipeline log breaks the count down: `decoys flagged via TSV Decoy column = N, via prefix scan = M`. `MarkingStats` replaces the prior `usize` return from `apply_library_decoy_marking` (`crates/osprey-core/src/types.rs`).

- **`scripts/build_entrapment_peptide_fasta.py`**: generates a peptide-level FASTA + FDRBench-style pairing manifest from a target uniprot FASTA. For each tryptic peptide it can optionally emit (a) an entrapment (`p_target`) peptide — deterministic shuffle with a fixed master seed, C-terminal residue preserved, per-peptide RNG seeded by SHA-1(sequence); (b) a decoy with a different master seed; (c) a `p_decoy` (shuffle of the entrapment). Each output FASTA entry carries the **source protein accession** (no per-peptide identifier in the accession), so multiple peptides from the same source protein share the same `ProteinID` in the resulting Carafe / DIA-NN library — Osprey's protein parsimony and picked-protein FDR work as on any normal library. Synthetic peptides that happen to collide with a real target are dropped quartet-wise, matching FDRBench's policy. Default decoy prefix is `decoy_`; default entrapment suffix is `_p_target`.

- **`scripts/fix_library_decoy_column.py`**: stream-processing utility that patches the `Decoy` column of a DIA-NN-style library TSV based on protein-accession prefix detection. Useful when Carafe generated a library with the `decoy_` / `rev_` prefix but left the `Decoy` column at `0` for all rows, which prevents DIA-NN (and historically Osprey) from recognising the decoys. **Not needed for Osprey workflows now that the loader reads both signals**, but kept around for DIA-NN-only consumers of the library.

## Bug Fixes

- **`decoys_in_library: true` and `decoy_method: FromLibrary` were silently broken.** The flag skipped Osprey's `DecoyGenerator` (as intended), but no code path detected decoys already present in the library — all four library loaders (DIA-NN TSV, blib, elib, libcache) hardcoded `is_decoy: false`. The `DecoyMethod::FromLibrary` enum variant additionally fell through to `Reverse` generation at the call site. Even if `is_decoy` had been set correctly, target-decoy `base_id` linkage was never established, so `compete_from_indices` and the LDA pairwise competition would have treated every entry as an "unpaired winner" — disabling the quality filter that target-decoy competition normally applies during SVM training. Net result: reported FDR was too optimistic in both modes. Fixed by the library-supplied decoy marking and the target-decoy pairing features above; the two settings are now equivalent and both produce correctly-flagged, correctly-paired decoys.

- **Repository line endings normalized.** The repo had a 51/73 CRLF/LF split with no enforcement, causing spurious whole-file diffs whenever a file was edited from the "wrong" platform. Added `* text=auto` to `.gitattributes` so Git stores all text files with LF in the index, and ran `git add --renormalize .` to flip the 51 CRLF files. Working-tree EOL still respects each developer's `core.autocrlf` setting — Windows sessions can keep CRLF locally if they prefer. No content changes from this normalization.
